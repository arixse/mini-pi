## 1. 定位：客户端不是"网页版 CLI"

最容易做错的一步是把终端那套一比一搬进浏览器。两者约束不同，界面就该不同：

| 维度 | CLI（REPL） | 客户端 |
| --- | --- | --- |
| 同时几个任务 | 一个进程一个回合 | 侧栏里多个 Run 并存，可来回切 |
| 历史 | 靠 `/load` 切会话 | 侧栏直接点，且**只读** |
| 审批 | 阻塞在同一个终端，只能回答当前那个 | 挂起成卡片，可先去看别的任务再回来 |
| 输出呈现 | 逐行流式打印，卡片与状态行 | 结构化时间线，可折叠、可复制、可回看 |
| 等待 | 人就在旁边 | 人可能切走了，所以要有通知与"挂起中"的显式提示 |
| 工作区 | `cd` 进去就是 | 常驻显示，切换要重建宿主 |

由此定下三条原则：

1. **状态永远可见。** 待审批徽标常驻顶栏，per-Run 的模型与上下文画在主列的状态行
   （第 20 条），默认模型与档位摆在输入区附加行的两个下拉里——任何时候都能回答
   "我在哪、用谁在跑、敢让它做什么"。
2. **等待必须被说出来。** 一个"什么都不动"的界面，用户分不清是卡住、是断线，还是在等自己裁决。
3. **界面不做能力墙。** 只暴露两个开关（隔离工作区、委派）。其余能力由模型调工具——把工具做成一排按钮，等于把"模型自己判断该用什么"退回成"人替它选"。

## 2. 信息架构：一屏四区 + 两层浮层

```
┌─ 顶栏 44 ─────────────────────────────────────────────────┐
│ logo 字标      待审批徽标        [通知][设置][主题][侧栏开关] │
├──────────┬────────────────────────────────────────────────┤
│ 侧栏 232  │ 状态行 36：指标-模型 / 指标-上下文（进度槽）/ 指标-步数 / 指标-缓存 │
│ 搜索      ├────────────────────────────────────────────────┤
│ 工作区 ─  │ 主区（时间线）：指令 / 工具调用 / 模型正文 / 审批卡 / │
│ ├ 工作区名│ 已入队 / 提示条，垂直滚动                         │
│ │ └ 会话 ├────────────────────────────────────────────────┤
│ └ …      │ 输入区：与会话**同宽**，不横跨侧栏                  │
└──────────┴────────────────────────────────────────────────┘
浮层：设置（模型 / 权限 一级分类）/ 变更 diff / 工作区选择
```

侧栏是**树形**的（工作区根 → 工作区名 → 会话），不再是"进行中 / 历史会话"
两段式：根行是纯分组标题，会话按所属工作区分组、各自独立折叠；行操作
（`+` 开新会话 / 行菜单）只在 hover 该行时出现，不常驻占位（见 handoff §4）。
多工作区下的会话寻址与启动恢复见 client-multi-workspace.md §5。

旧版时间线顶部的 sticky 运行头已被**状态行**取代：运行头跟着 Run 走，而
"我在哪、用谁在跑、上下文占到多少"是整个界面的常驻上下文，切会话、看历史时
都该在场——所以它升一格变成主列顶部固定的一条（36px），只属于主列
（分隔线从侧栏右缘起），且没有工作区时整个不渲染（空态里一行指标反而像误渲染）。

实现仍是 `grid-template-columns: auto minmax(0,1fr)` + 输入区 `grid-column: 2`，
而不是"整行铺一个页脚"——后者在 flex 一行里很自然，但会把输入框推到侧栏宽度之外。

四区的分工是"谁会一直变"：顶栏是常驻上下文，侧栏是导航，主区是被执行的内容，输入区是唯一的入口。
主区之外的三块都不随执行过程重排，否则每次流式输出都会让人找不到刚才在看的东西。

## 3. 组件与状态清单

| 组件 | 必含状态 | 数据从哪来 |
| --- | --- | --- |
| 顶栏 | 品牌 + 待审批徽标（无挂起时隐藏，点击跳最早挂起的）+ 图标组（通知 / 设置 / 主题 / 侧栏开关） | `/api/state` |
| 状态行 | 指标-模型（当前 Run 实际用的）、指标-上下文（token / 窗口 + 进度槽，≥80% 警戒）、指标-步数、指标-缓存（`cacheRead / input`；提供方未返回时显示「—」） | 当前 Run + 事件流 |
| 侧栏·树 | 顶部搜索框（按工作区名模糊过滤，见 client-multi-workspace.md §5）；工作区根（纯分组标题、池内会话计数）；工作区名（会话计数、独立折叠、选中态）；会话（条数、是否已压缩）；行操作 hover 才出现 | `/api/sessions` |
| 用户气泡 | 提交中 / 已入队（**空心描边** + 元信息行 + 「撤回」） | 本地 + 排队取消 |
| 模型气泡 | 流式（光标）/ 完成（复制按钮 hover 出现） | `message_update` |
| 工具卡片 | **单行** + 生命周期标记（● 运行中 / ✓ 完成 / ✖ 错误）；结果超长才给"展开全部" | `tool_execution_start / end` |
| 待审阅的隔离改动条 | 当前工作区所有 `isolated && !released && !merged` 的 Run；标题 + 状态 + 「看变更」；运行中 / 排队 / 等待裁决时按钮禁用 | `/api/state` 的 `runs` |
| 审批卡 | 无风险 / 中等 / 高危；动作行三个（允许一次 / 本会话全部允许 / 拒绝）；等待中 / 已裁决 / 已失效（Run 被取消） | 内核结构化 `ApprovalRequest`（等级 + 原因 + 摘要） |
| 变更面板 | 文件条 + diff 体（五个专用 diff token）+ 应用变更 / 放弃变更 / 返回审批；从改动条进入 | `GET /api/runs/:id/diff` |
| 提示条 | warn（挂起、降级）/ error（流断、请求失败）/ ok（完成、隔离提示） | 本地 + 服务端错误 |
| 输入区 | 附加行两个下拉（模型 / 权限，答"新任务用什么"）；空闲 / 忙碌（发送键换成停止键，**输入照常排队**）/ 未配模型（禁用并给理由）；Enter 发送、Shift+Enter 换行、Tab 排队下一条 | `/api/state` |
| 设置面板 | 一级分类「模型 / 权限」；模型页：九家供应商平铺 + 自定义供应商区（名称 / Base URL / API Key）；权限页：档位三选一；密钥"已配置，留空不改" | `/api/providers`、`/api/model` |

## 4. 画布十帧（重做后的视觉基准）

视觉稿重做后是 Ardot 画布上的**十帧**（上排五帧 Dark、下排五帧同名 Light，
每帧 1280×900；排布见 handoff §1）。每帧要回答的问题：

| 帧 | 要回答的问题 |
| --- | --- |
| 01 执行中 | 正常态长什么样：指令 → 工具调用 → 模型正文 → 审批 → 已入队，顺序即时间顺序 |
| 02 高危审批 | `rm -rf` 这类怎么呈现，为什么高危不叠加降级理由 |
| 03 变更 diff | 隔离工作区下改了什么，落地前先看（应用变更 / 放弃变更 / 返回审批） |
| 04 设置 · 模型 | 九家供应商平铺 + 自定义供应商区；密钥只写不读；本屏没有审批档位（归权限页） |
| 05 空态引导 | 没工作区、没模型时界面说什么，而不是一片空白 |

桌面壳不引入第二套界面：同一份 Web 产物装进原生窗口（见 §7）。

## 5. 已定决策

编号与静态稿的标注一一对应。

1. **工作区常驻侧栏树根。** 模型读写的是哪个目录，任何时候都不能靠猜：根行
   「工作区」常显池内会话计数，其下每个工作区名节点独立折叠、点击聚焦
   （新任务发到这里）；空态时侧栏与主区各留一条提示引导选择。
   （重做前它顶着顶栏一枚芯片，重做后顶栏只留全局动作，导航归侧栏；
   多工作区后的三层树见 client-multi-workspace.md §5。）
2. **模型与审批档位并排，摆在输入区附加行。** "新任务用谁跑"和"敢让它做什么"是
   同一组信息，两个下拉并排放在输入区——改默认值的时刻正是"准备说下一句话"的时刻；
   档位的正式编辑在设置的权限页，输入框内的切换是临时的。
3. **待审批常驻计数 + 一键跳转。** 唯一会让人干等的事件，不能只在时间流里冒出来一次。
   顶栏徽标显示待审批数，多个 Run 同时挂起时按**最早挂起**的那个跳，并滚到它
   时间线里的审批卡——计数是聚合的，落脚点必须是具体那一张。
4. **状态行常驻主列顶部。** 滚到长输出中间时，"用谁在跑、上下文占到多少、走到第几步、
   缓存命中如何"始终在手边。它答的是"当前这个任务"（模型、token、步数、缓存命中率），
   与输入区下拉答的"新任务用什么"分工明确（第 20 条）；旧版这条信息长在 sticky 运行头里，
   重做后升为主列常驻的一条。缓存命中率没有数据时显示「—」而不是 0%——后者会被读成
   "缓存一次都没生效"，而真相是"提供方没返回这个字段"。
5. **用户靠右、模型靠左，气泡最大宽度 85%。** 长行不贴边，窄屏也不至于挤成一列。
6. **工具卡片四态靠"配色 + 文字"双重编码。** 只看颜色的话，色弱用户与截图场景都读不出来。
7. **工具参数必须渲染。** 只写"跑了 grep"等于让用户信任一句没有证据的话。
8. **风险等级与命中原因由内核算好**（`packages/core/src/risk.ts`），前端只负责配色与按钮。否则同一条 `rm -rf` 在终端和 Web 可能给出不同等级——而等级是安全语义，不容许两端各判一次。
   **「总是允许」的范围同样两端同义**：与 CLI 的 `a` 一样是**本会话内**（不是"本轮"、更不是全局），记账在内核，前端只发选项。
9. **挂起要显式说出来。** 顶部提示条 + 卡片"等待确认"，避免把"在等你"误读成"卡住了"。
   等待时长实时显示；**审批不设超时**——与 CLI 一致，人不在场就一直挂着，超时自动放行或自动拒绝都比"等人"更危险。
10. **高危单独成块（rose），不叠加降级理由。** 一次列五条"删除文件/网络请求"会把最致命的那条淹掉。
11. **窄屏侧栏收成抽屉**，不是挤成一条。挤成一条等于同时失去导航和内容。
12. **输入区只放两个开关。** 见第 1 节原则 3。
13. **没配模型也要能开。** 服务照常起，只是发不出任务。输入区必须说清缺的是
    "选模型"还是"补 Key"：已经选了供应商却没存 Key 时给的是补 Key 的下一步，
    而不是笼统的「尚未配置模型」。
14. **空态即引导。** 说清缺的是哪一样（工作区 / 模型），并给直达按钮。
15. **历史会话只读。** 切过去就换 store；删除当前会话回到草稿态（会话是懒创建的，
    服务端不再"顺手补开一个新会话"）。删除本身要二次确认。只读只限制"发新消息"：
    这段历史里如果还挂着一条 live Run，输入区仍显示停止键——停任务不该因为
    当前看的是历史而被藏起来。
16. **隔离工作区的 diff 在落地前给，入口在主列顶部。** "改完再决定去留"缺了这一步就只是换了个说法的盲改。主列的「待审阅的隔离改动」条列出当前工作区所有未合并、未丢弃的 Run（不只正在看的那条），每条一个「看变更」；Run 还在运行 / 排队 / 等审批时按钮禁用（服务端读 diff 会 409），结束后才可点。审批卡上不再放必然 409 的「看变更」。
17. **密钥只写不读**，前端永不回显明文；档位认不出时报错而不是回落默认值。
18. **输入区与会话同宽**，不横跨侧栏。输入框是"对话的一部分"而不是页脚：
    跨过去之后，视线必须先越过侧栏宽度才能落笔，长会话里尤其别扭。
    侧栏竖向贯穿到底，主区与输入区共用第 2 列。
19. **输入框默认三行高**（68px），随内容长到约八行（208px）后内部滚动。
    一行高写长要求时只见得到开头一截，而这类输入恰恰最需要回看；
    给默认高度而不是只靠自动撑开，是为了让用户**一开始就看出这里能写多段**。
20. **输入区下拉是"默认值"，状态行才回答"用谁在跑"。** 附加行的模型/权限下拉说的是
    "新任务会用什么"；每个 Run 实际用的模型与上下文画在状态行。侧栏允许多个 Run 并存，
    而"切换后新任务立即生效"意味着不同 Run 可以是不同模型——这时候一枚全局芯片
    答不出"用谁在跑"，所以这个答案必须挂在 Run 上（第 1 节原则 1 的同名说法以此为准）。
    （重做前默认值顶着顶栏芯片、per-Run 画在运行头，重做后分别挪进输入区与状态行，
    分工没变、载体换了。）
21. **运行中输入照常排队，发送不禁用。** 与 CLI 同一口径（busy 时排队、回合结束后
    执行）；排队条目在时间线里标"已入队"（空心描边）。忙时发送**不切换当前视图
    的 Run 订阅**——正文、审批卡和滚动位置都留在正在跑的那条；当前 Run 收尾后
    自动接管队列里的下一条。挂起（等审批）与运行中一样能输入——终端里做不到
    这件事，正是客户端"不再阻塞"的那一半价值。
22. **Run 完成后可续聊。** 发送即开新任务、沿用同一会话——Run 是一次执行，会话是
    一段对话，两者不是一回事。隔离工作区的 diff 未落地前，主列顶部的改动条
    一直保留，别让"改完还没落地"这件事在续聊时被忘掉。
23. **档位切换不追溯。** 只影响之后的工具调用；已挂起的审批卡仍等人裁决，
    既不自动放行也不自动作废。审批是真防线，切换档位不该悄悄改写一次已发出的提问。
24. **Esc 只收界面层，不停任务。** 浮层 → 待删确认 → 抽屉逐层收起，收完就什么都不做；
    停任务只能由输入区的「停止」（运行中时发送键原位变成停止键）显式发起。在输入框里
    按一下 Esc 就把正在跑的任务停掉，代价远大于省下的那一次点击。
25. **隔离是运行时可切的开关，只影响之后的任务。** 环境不支持时拒绝打开并给出具体原因；
    关掉可以退回共用目录——启动参数不该把用户锁死。合并成功后 worktree **不自动回收**，
    删除仍由「丢弃」显式发起；合并不制造提交，只把 patch 应用到主工作区。
    还有未合并隔离改动时，「关闭工作区」回 409 并指回主列顶部；进程退出没有界面，
    保留 worktree 并把路径写进日志，绝不静默删除用户产物。
26. **通知要用户手势才申请，且只提醒"需要人"的事件。** 顶栏铃铛第一次点击申请权限；
    挂起与后台结束各提醒一次（`tag` 去重），正在看且前台时不弹。没权限时只在标题上
    留 `(n)` 并说明去哪改，不反复弹权限框；通知只做提醒，不做收件箱。

## 6. 数据边界：前端不做什么

| 事 | 谁做 |
| --- | --- |
| 风险等级、命中原因 | 内核（`packages/core/src/risk.ts`），前端只配色 |
| 工具调用的摘要文案 | 内核 `describeToolCall`，终端与 Web 说同一句话 |
| 执行编排、取消、并发上限 | 内核（`packages/core/src/run.ts`、`runManager.ts`） |
| 事件流 | 服务端 SSE，按游标续传；当前 Run 的正文走 per-run 流，所有 Run 的生命周期与审批走 `/api/events`（见 [client-event-stream.md](./client-event-stream.md)） |
| 前端不做的 | 不评估风险、不压缩会话、不直连模型、不读密钥明文 |

判据是"这条语义两端必须一致"：凡是一致性有代价的，都由内核产出**数据**，前端只做**呈现**。

**没有令牌门禁。** 服务只监听 `127.0.0.1`，本机自用是主要用法；每开一次浏览器都要贴一次令牌，
换来的是一层"防自己人"的摩擦，不值得——所以稿子不做门禁页。**这条是前提，不是结论**：
哪天要支持非本机访问（局域网、远程开发机），访问令牌是第一批要重新摆上桌的东西。

## 7. 响应式与桌面壳

- **1180**：侧栏常驻（稿子默认）。
- **880**：侧栏仍常驻，主区气泡宽度收窄——这是多数笔记本外接显示器的实际宽度。
- **420**：侧栏变抽屉（overlay + 半透明遮罩），顶栏出现汉堡入口。

桌面壳（M5）不引入第二套界面：主进程只做起服务、开窗口 `loadURL`、关窗退出三件事，
窗口内就是同一份 Web 产物。这样桌面端不会长出"只有桌面端才有的 bug"。

## 8. 待定问题

- **通知形态与去重**（已定）：标题角标 `(n) mini-pi` + 顶栏铃铛。第一次点铃铛才申请权限；
  挂起按审批 id、结束按 Run id 各提醒一次（`tag` 去重，重连重放不会重复弹）；
  正在看且页面在前台时不弹，切走或切后台才提醒。不做通知中心，也不做"一键全清"——
  系统通知由操作系统管理，关掉铃铛即可停止后续提醒。刷新页面靠 `journal_ready`
  挡住补历史的旧事件，不会把几天前的挂起重弹一遍。
- **diff 的粒度**（已定其一）：当前实现是"整个 Run 一份 patch"，按文件逐个确认合并尚未提供；
  先整体审阅、一次性落地，冲突时整份都不会应用。
- **合并冲突**（已定）：apply 前先 `--check`，冲突就 409 并**保留 worktree**，把涉及文件列出来；
  用户自己处理主工作区后再试——不做自动合并策略，也不静默覆盖。
- **委派（子 Agent）的可视化**：现在是工具卡里的一行，是否要展开成嵌套时间线——取决于 M2 落地后真实调用的密度。
- **历史会话的搜索**：服务端目前没有检索接口，所以侧栏搜索框不暗示"能搜内容"；
  它的口径是**按工作区名模糊匹配**（见 client-multi-workspace.md §5），
  不再按任务名 / 会话标题过滤。
- **多工作区**（已落地，见 [client-multi-workspace.md](./client-multi-workspace.md)）：
  同一时刻可有多个工作区并存、互不打断——服务端是宿主池（上限默认 4），
  侧栏三层为「工作区 → 工作区名 → 会话」；切走只挪焦点，只有显式
  「关闭工作区」才结束里面的任务。
