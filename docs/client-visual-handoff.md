## 2. 版式与栅格

单屏四区，从顶到底：

| 区域 | 高度 | 说明 |
|------|------|------|
| 顶栏 | 44 | logo + 字标 + 待裁决徽标 + 右侧图标组（通知 / 设置 / 主题 / 侧栏开关） |
| 状态栏 | 36 | 指标-上下文（含进度槽）、指标-步数、指标-缓存 |
| 侧栏 | 264–320 宽 | 树形：工作区根 → 工作区名 → 会话；行操作 hover 才出现 |
| 主列 | 760–1280 宽 | 左右留白 12–28，垂直滚动 |

侧栏 232 / 主列 760 是 1280 画布上的**基准值**，不是运行时固定值：实际窗口
从 880 到 4K 都要能用，所以两条宽度走 `clamp()`（侧栏 `264 → 320`、主列
`760 → 1280`），留白走 `clamp(12px, 1.6vw, 28px)`。断点见
[client-ui-design.md](./client-ui-design.md) §7：1199 收间距、1023 侧栏 240、
879 抽屉、559 手机。

- **圆角体系**：卡片 10、输入框 7~8、聊天气泡 14（用户 `14/14/4/14`、助手 `4/14/14/14`）
- **字号**：页标题 17~18、卡标题 13、正文 12.5~13.5、辅助 11~11.5
- **等宽**：路径、命令、token 数一律 JetBrains Mono；正文与 UI 用 Inter
- **色板分层**：背景从 `bg-canvas` → `bg-sidebar` → `bg-raised` → `bg-code` 依次抬升，
  **靠亮度分层，不靠 1px 描边分层**

## 3. 十屏清单与验收要点

### 01 执行中（主屏）

转录列四块加一个新块，顺序即时间顺序：**指令 → 工具调用 → 模型正文 → 审批 → 已入队**。

- 指令块：用户头像 + `accent-soft` 实心气泡 + 时间戳，右对齐
- 工具调用：**单行**，生命周期标记 `● 运行中 / ✓ 完成 / ✖ 错误`，不套三层盒子
- 审批块：`warn-soft` 底，动作行四个（允许一次 / 本会话全部允许 / 拒绝 / 看变更）
- 已入队块：**空心描边气泡**（区别于已执行指令的实心），元信息行"已入队 · 当前回合结束后执行"
  + 右侧「撤回」
- 输入区：附加行放模型与权限两个下拉，输入框 68px，底部一行放隔离工作区 / 委派子 Agent
  两个开关 + "发送"与"停止"**同一个按钮两种状态**

### 02 高危审批

审批框整体换成 `danger-soft`，标题带"高危"，目标区显示完整命令，变更规模提示"不可撤销"。
顶栏徽标显示"1 待裁决"。

### 03 变更 diff

隔离工作区的**落地前预览**：面板头 `+54 / −6`，文件条 + diff 体 + 动作行
（应用变更 / 放弃变更 / 返回审批）。diff 行走 `diff-add-bg` / `diff-del-bg` /
`diff-add-text` / `diff-del-text` / `diff-gutter` 五个专用 token，**不要复用语义色**。

### 04 设置 · 模型

九家供应商按内核注册顺序平铺，行 = 名称 + 接入地址 + 配置状态。选中行（DeepSeek）
向下展开凭据编辑区。底部是**自定义供应商区**（名称 / Base URL / API Key）。

**本屏没有审批档位**——审批档位归权限页，与供应商无关。

### 05 空态引导

首次启动、还没有工作区。侧栏只留一句提示，主区居中放品牌标识与"选择目录…"动作。

## 4. 静态稿画不出来、但必须实现的交互

- **侧栏行操作默认不占位**：工作区行是 `+`（在该工作区开新会话）与 `···`
  （关闭工作区）；会话行是 `···`（删除会话）。只在 hover 该行时出现。
  重命名 / 分叉 / 归档 / 迁移等动作要等服务端有对应接口后再进菜单。
  这是 deepseek-harness 的约定——常驻按钮会吃掉近 1/3 行宽。
- **工作区行的折叠箭头同样是 hover 才出现**，层级靠缩进表达（根 4 / 工作区 11 / 会话 18）。
- **主题切换**：顶栏右上角，只切根节点 `data-theme`，不重画、不换色值。
- **排队消息可撤回**：内核已支持（见 §5）。

## 5. 内核缺口（开发前要补）

1. **自定义供应商**（已补）：`ModelProviderService.saveProviderConfig()` 原先只接受**已注册**的
   provider 名，自定义名称会被直接抛错。现在未注册名 + Base URL 会当场建成一个
   OpenAI 兼容的 `CustomProvider` 槽位，存成 auth.json 里带 `custom` 标记的独立条目，
   不覆盖官方凭据；`loadCustomProviders()` 负责重启后注册回来，CLI 与客户端
   经同一个收口（`createModelFromSettings` / host `start()`）加载。细节见
   [providers.md](./providers.md) 的自定义供应商一节。
2. **权限页**（已补）：审批档位（只读 / 工作区写 / 完全访问）做成设置里的一级分类，
   与供应商页并列；输入框内的临时切换保留在发送区。
3. **排队条目取消**（已补）：`RunManager.cancelRun` 对排队中的 Run 直接出队并给 cancelled
   结论；客户端的停止键（输入区发送/停止同一个按钮）与排队气泡上的「撤回」都接到这个出口。
4. **状态栏上下文用量**（已补）：分母来自 `settings.json` 的 `contextWindow`，缺省按模型名推断
   （见 [providers.md](./providers.md) 的上下文窗口推断表）；状态栏常驻显示百分比，
   ≥80% 变色提示。

## 6. 文案红线

界面文案**不出现**实现细节：文件路径（`~/.mini-pi/auth.json`）、权限位（0600）、
内核注册顺序、源码路径（`packages/core/src/provider`）都不写。
要表达"密钥只保存在本机、不会上传、不回显原文"这类**用户视角的承诺**。

## 7. 不要复刻旧静态稿的问题

旧静态稿 mockup.html（已删除）的六个缺陷是这次重做的出发点：

1. 三个背景色亮度差不足 6%，只能靠满屏 1px 描边分层
2. 用户气泡用最大视觉权重（实心高饱和），而工具输出被裁到 148px —— 信息权重与视觉权重倒挂
3. 一张 grep 结果套了三层边框、两层背景
4. 48px 顶栏塞了 8 个元素
5. 五个语义色加渐变色品牌名，主色不再主
6. 审批卡和工具卡长得一样，分不出紧急程度
