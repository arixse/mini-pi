## 多 Agent 专项评审（只审查、未改代码，含实测）

针对 subagent.ts / subagentTool.ts / roles.ts / loop.ts / repl.ts / approval.ts / render.ts 通读 + 临时脚本实测（脚本已删，工作区干净）。

**实测确认的两个缺陷**（ts 临时脚本 esbuild bundle 后 node 运行）：
- `SubAgentSupervisor.acquire()` 预算可被突破：醒来后不二次检查 `delegations`。maxDelegations=8 / maxParallel=4、并发申请 12 次 → 12 次全部放行，记账 delegations=12。根因：budget 检查在 `await` 之前，排队唤醒后直接 `delegations += 1`。
- 排队中的委派对取消无感知：`while (running >= maxParallel)` 的等待没有与 parentSignal 竞速，父 abort 后排队者仍挂着 >1s（实测 STILL_WAITING）。与上面那条 P0 是同一处 `acquire`。

**其余结论（按主题）**：
- 成本：只有次数预算，缺 token/wall-clock 预算；主循环 100 轮 × 8 次/轮 = 单次会话理论上限 800 次委派；子 Agent 无整体超时；探索类角色仍用父模型（设计稿的 `model` 参数未落地）。

## 落地 A 批 + /subagent 开关（feature/multi-agent：f1c1e27、66f25c8）

**A 批**（`subagent.ts` `SubAgentSupervisor.acquire`）：预算检查移到 `await` 之后（`while running>=maxParallel && !aborted` + `waitForTurn`），拒绝前 `wakeAll()`；父信号已取消时直接返回 `cancelled`（旧行为是发已 abort 的槽位，子 Agent 仍会跑起来白占额度）；返回 `AcquireResult` 可辨识联合，`subagentTool.ts` 的 `describeDelegationDenied` 分别回「预算用完→合并任务」与「已取消→别重试」。
踩坑记录：
- 补 A1 用例时不能 `await Promise.all(12 个 acquire)` 再释放——只有 maxParallel 个会先 resolve，其余永远等不到 release → 用例自身死锁。要按"拿到名额的跑完再 release"分批推进。

**/subagent 开关**：关闭时从本回合工具列表摘掉 `task`（`activeToolRegistry`），而不是调用时报错——后者会让模型每轮先试着派一次。状态写 `settings.json` 的 `subagentEnabled`，只有布尔 `false` 算关闭（与 maxTokens/contextWindow 的"非法值当没配"同口径）；写盘失败时开关仍在本会话生效但如实提示。`/status` 关闭时占一行并显示怎么再打开。实现拆成 `activeToolRegistry` / `parseSubAgentCommand` / `applySubAgentCommand` 三个纯函数，REPL 只负责打印与接线。
