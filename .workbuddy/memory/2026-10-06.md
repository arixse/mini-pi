## 全量代码审查：优化点清单（未改代码，仅分析）

基线：`tsc --noEmit` 全绿；`tsx --test` 557 例 / 474 pass / 80 fail，
80 个失败全部集中在 `src/agent/tools.test.ts`（`beforeEach` 的 `rmSync(.test-workspace)`
命中 safe-delete 批量删除护栏，非代码缺陷）。

P0（正确性）：
- `sessionStore.summarizeEntries` 非取消失败会回退 `generateSimpleSummary` 并**写入** compaction
  条目，与 `compactIfNedded` 注释里"取消才不写"的意图相悖；且摘要输入未做 token 预算，
  超窗 400 是常态路径 → 真实历史被换成统计数字。
- `repl.ts` 的 `rl.on("line")` 是 async 且无串行化，模型思考期间再输入一行会并发跑第二轮
  `runAgentLoop`，`activeRun` 被覆盖、两轮交错写会话文件。
- 审批 `confirm` 未先 `status.stop()`，spinner 每 100ms 覆写同一行，确认提示被擦。
- `approval.ts` 的 `AUTO_APPROVED_TOOLS` 只有 list_files/read_file，
  与 registry 的只读集合（含 glob/grep）不同步，存在两处事实来源。

P1（性能）：
- `buildContext()` 每轮被调用 3~5 次（willCompact / needsCompaction / compactIfNedded / /status），
  每次全量 pathToLeaf + 全量 token 估算。
- `contextOverheadTokens` 每轮 `JSON.stringify(tools)` + 逐字符扫 systemPrompt。
- `createWorkspaceIgnore` 每次工具调用都重读 .gitignore 并重建 matcher。
- grep 在 walkEntries 里串行读文件。
- `/model` 拉模型列表的 `fetch` 无超时/取消/缓存（聊天链路有 120s + 看门狗，这条是裸的）。

P2（工程）：
- 8 个零引用依赖（express/react/react-dom/vite/lucide-react/concurrently/dotenv/
  @vitejs/plugin-react）+ `vite.config.ts` / `index.html` 是第二阶段遗留。
- 死类型：`AgentEvent` 的 compaction/branch_switch 从未发出；SessionResponse 等零引用。
- `usage` 全程采集但从未聚合展示（README 声称 /status 显示"用量"）。
- 模块级全局 `toolStartCache` / `lastToolCall` 跨会话残留。
- entry.ts 无参数解析，不支持 `--help` / 非交互 `-p`。
- 会话文件名秒级时间戳会撞名；`write_file`/`edit_file` 未做原子写（凭据文件已做）。
- typo：`compactIfNedded`、`Unkownn session entry`。
