## CLI 展示层收尾：审批 [y/N/a] + 风险着色 + /status 折行 + 命令清单注册表

延续 2026-10-10 的 CLI 展示优化，把剩下的 P2 都做掉了（commit `4c037ca`）。

### 做了什么

- **审批 `ApprovalAnswer`**：`confirm` 的返回值从 `boolean` 换成
  `"yes" | "no" | "always"`。`a`（本会话全允许）没法用真假两态表达；
  Fail closed 的语义没动，直接回车仍算拒绝（与 `[y/N]` 里 N 大写一致）。
- **`assessToolRisk`**：在审批这一层再评估一遍风险——沙箱只挡越界路径，
  挡不住 `rm -rf build` 这种**合法但致命**的命令。high 与 elevated 两档，
  **命中 high 时不叠加 elevated**（一次列五条会把致命那条淹掉）。
- **版式收编**：审批提示改用卡片的 `│ / └`（ASCII 降级 `| / +`），
  此前它自成一套三空格缩进。
- **`onSessionAllow` 回写 `trusted`**：用户按 `a` 而不回写的话，
  `/status` 会显示"需确认"而实际已经不问了——状态与实际不符比少一次确认更危险。
- **`/status` 长值折行**：新增 `width.wrapToWidth` / `terminalWidth`，
  续行缩进到值起点；值列保底 24 列。
- **命令清单单一注册表 `src/cli/commands.ts`**：`/help` 与启动欢迎语都从它渲染，
  并用 `commands.test.ts` 双向比对 注册表 ↔ `repl.ts` 分派分支 ↔ README ↔ cli-interaction.md。

### 踩到的坑

- `padToWidth` 在文本恰好等于目标宽度时会多补一个空格（保证标签与值之间有间隔），
  用它排 `/help` 的用法列会导致最长那一行偏移一列；对齐到固定列宽应自己补空格。
- `wrapToWidth` 折出来的行要 `trimEnd`：`"aa   bb"` 在 3 列宽下会得到 `"aa "`，
  尾随空格在终端里看不见却会让断言失败。
- 续行缩进容易差一格：`│ ` 的 gutter 只占 1 个字符，挂行缩进应是 `valueStart - 1`
  而不是 `valueStart`。
- 给 `describeToolCall` 加 `task` 分支时发现多行命令/goal 会让正文掉出 gutter，
  补了 `oneLine` 压平——提示语每行只有一个 gutter 前缀。

### 过程中发现并修掉的真问题

1. **超时信号接错地方**：`linkSignals(...)` 的返回值建好却没下发，循环拿到的是另一个
   只监听父信号的 controller，于是 `timeoutMs` **永远不生效**。是测试先发现的
   （`result.timedOut` 恒 `undefined`）。
   教训：多路信号合并时，"哪个 controller 记哪个原因"必须和"下发给循环的是哪个"一起验证。

2. **`ok` 判定的用例走不通真实链路**：`loop.ts` 一遇 `stopReason === "error"` 就
   `finishTurnEarly`，而网络重试发生在 model provider 内部（不进历史）。
   所以 `[error, stop]` 只能直接喂消息列表——这反过来证明成败判定本就该抽成纯函数。

3. **`/subagent trace` 写盘失败时丢弃了 `traceEnabled`**：恰好在用户最需要 trace 的时刻
   让它不生效，且与委派开关的 `persistFailed` 处置不一致。已统一为"本会话照样生效 + 告警"。

4. **E3 的测试纠正了我的预期**：父表只读 + `allowBash:true` → 判**可并发**是对的
   （父表没有 bash，申请了也拿不到，实际能力确实只读）。E3 的口径就是"实际能力"，不是"名义角色"。
