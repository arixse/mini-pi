- **provider 拉模型列表的 `fetch` 全部无超时/无 signal**：7 个 provider（anthropic / deepseek /
  kimi / mimo / minimax-cn / openai / zhipu）都是裸 `fetch(getModelsUrl(...))`，
  上游挂死时 `/model` 会永久卡住。模型请求侧已有 120s 超时 + 静默看门狗，这一侧没有。

### 顺带查出并修掉一个真 bug（不是环境问题）

修完卫生问题后 tools.test.ts 仍剩 2 例失败（`真实超时应被终止并标注 timedOut`、
`失败结果必须标记 isError`），根因**不是沙箱**：

- `killProcessTree` 里 `spawnSync("taskkill", ...)` 后**无条件 `return`**，
  而 `spawnSync` 在可执行文件起不来时**不抛异常**，只把错误放进返回值
  （实测本机沙箱：`spawnSync taskkill EBUSY`、`status: null`）——
  于是 `catch` 永不触发、`child.kill("SIGKILL")` 永远不可达，超时静默失效。
- 修法：新增导出纯函数 `taskkillSucceeded({error,status})`（仅 `status === 0` 且无 error
  才算成功），`killProcessTree` 据此判断，失败则回退 `child.kill("SIGKILL")`。
- 补回归用例：`describe("taskkillSucceeded（超时终止的成败判定）")` 覆盖
  success / EBUSY(status null) / status undefined / 非零退出四种输入。
